## 基本の流れ

1. 動画や音声のあるページを開いて**再生する**
2. ツールバーの Media Sniper アイコンをクリック
3. 一覧に出たアイテムの「保存」を押す
4. ブラウザのダウンロードバーに進み、`~/Downloads` にファイルが届く

重要なのは「**再生した（またはページが読み込んだ）メディアだけが対象**」という点。拡張はページ内のネットワーク通信とプレイヤー要素を見ていて、あなたが再生を始めたタイミングで初めてリストに現れます。ページを開いて何も再生していない状態で一覧が空なのは正常な動作です。

## 検出の仕様

### 一覧に出るもの

| バッジ | 意味 | 保存されるファイル |
|---|---|---|
| 動画 | 単体の動画ファイル（mp4/webmなど） | そのままの形式 |
| HLS | ストリーミング配信（.m3u8） | 結合・変換済みの **.mp4** |
| 音声(HLS) | 音声だけのストリーミング | .aac |
| 音声 | 単体の音声ファイル（mp3/m4aなど） | そのままの形式 |
| DASH | ストリーミング配信（.mpd） | 結合済みの **.mp4**（または音声.m4a） |

アイテムごとに、サイズ（分かれば）・長さ（分かれば）・検出経由が小さく表示されます。

### 解像度が複数出るとき

- HLSの高品質配信は「720p」「1080p」のように**解像度ごとに別アイテム**になります。欲しい画質のものを保存してください
- YouTubeでは `[360p]` のようなプログレッシブ形式に加えて、**`[1080p]+音声`** のような結合用アイテムが出ます。これは映像と音声を別々に取ってきて自動で1本のmp4にまとめるもので、1080p以上の画質はこちらを使います。`[音声のみ]` は音声だけ欲しいとき用です

### 再スキャン / クリア

- **再スキャン**: 今開いているページをもう一度調べます。拡張を読み込んだ後に再生し始めた場合などに使います
- **クリア**: 今のタブの検出一覧を空にします。ファイルには影響しません

## 保存ボタンの挙動

押した後のボタンの変化で進行状況が分かります。

**単体ファイル（動画/音声）**
即座にダウンロードキューに入り、「キュー追加」→ 数秒で完了。同時に最大3件ずつ処理され、残りは順番待ちします。

**HLS / DASH（ストリーミング）**
1. 「取得中」または「〇〇%」— セグメント（分割データ）を集めています。**動画の長さに比例して時間がかかります**（10分のアニメで数十秒〜数分程度が目安）
2. 「保存中」— 結合したファイルをDownloadsへ書き込み中
3. 元に戻る — 完了。ステータス行に保存先ファイル名が出ます

処理中でもページ遷移やブラウザ操作は自由ですが、**そのタブを閉じると取り込みは止まります**。

**ライブ配信（HLS）**
「録画中」と表示され、経過時間とサイズが増えていきます。この状態でボタンが「停止」に変わるので、**録りたいところで停止を押す**とそこまでの内容がfragmented MP4として保存されます。ライブは最初から最後まで一気に取れるものではないので、必要な区間を録画する形になります。

**失敗したとき**
CDNが403などで拒否した場合、自動で「再試行中」になり、ページ自身が使っていた認証情報付きでもう一度試します（ステータス行に説明が出ます）。それでもダメなら「失敗: …」と理由が表示されます。もう一度「保存」を押せばやり直せます。

**yt-dlp コマンドボタン**
今のページURLで `yt-dlp` コマンドを作ってクリップボードにコピーします。Media Sniperで取れない難しいケース（認証が特殊なサイト等）の代替手段。ターミナルに貼って実行する用で、これ自体にはMedia Sniperの機能は関係ありません。

## 全部保存

ツールバー上部の「**全部保存**」を押すと、一覧のアイテムを一括でキューに入れます。

- 通常のファイルはまとめてキュー投入（同時3件で順次消化）
- **HLS/DASHは1件ずつ順番に**処理されます（変換エンジンは同時に1つしか回らないため）。5本のHLSがあれば、終わり次第次のHLSが自動で始まります
- **保存済みスキップ**: 以前保存したことのあるファイル名と同じ名前がブラウザのダウンロード履歴に見つかった場合、そのアイテムは「保存済み」扱いでスキップします。同じページで再度全部保存しても、新しく増えたものだけが取れます
- ステータス行に「◯件キュー追加 · ◯件スキップ · ◯件順次処理中」と結果が出ます

## ファイル名と保存先のルール

1. **基本**: ページタイトルや動画タイトルを使います（`アニメ 第12話.mp4` など）
2. タイトルが取れない場合はURLの末尾部分（`video_abc123.mp4` など）
3. それもなければ `media-sniper_video.mp4` 形式のフォールバック名
4. **同名ファイルがある場合は上書きせず `名前 (1).mp4` と番号を付けて両方残します**（設定に関係なく常にこの挙動）

保存先は:

- 既定: `~/Downloads` 直下
- 設定でルートフォルダを指定している場合: `~/Downloads/<ルートフォルダ>/` の下

Windows/macOSのファイル名に使えない文字（ `/ \ : * ? " < > |` ）は `_` に置き換えられます。

## 設定画面の各項目

ポップアップ右上の ⚙ から開きます。変更は「保存」を押した瞬間から有効（ブラウザの再起動は不要）。

### 保存先フォルダ名

- Downloadsの中に作るフォルダ名。例: `media-sniper` と入れると `~/Downloads/media-sniper/` に保存される
- **空欄なら Downloads 直下**（フラット保存）
- 入力のルール: スラッシュや使用不可文字は `_` に置き換わります。絶対パス（`/Users/...` 等）や `..` を含む入力は保存時に空欄扱いになります（安全のための制限）。階層を作りたい場合は `a/b` のように相対的な形で書けば `a/b` フォルダとして作成されます

### 最小サイズ (KB)

- これより小さい単体メディアは「広告・アイコン・トラッキング画像」扱いで**一覧に出なくなります**
- 既定は 500（= 0.5MB）。VHD系ダウンローダと同じ基準
- 小さい正片を拾いたいサイトでは数値を下げる。逆にノイズが多いなら上げる
- **0で無効化**（すべてのサイズを候補にする）。ストリーミング(HLS/DASH)はサイズ不明なので、この設定の影響を受けません

### 除外ドメイン

- ここに入れたドメインからのメディアは**検出自体を行わなくなります**
- 書き方はカンマ区切りか改行区切り。例:
  ```
  ads.example.com, tracker.io
  count.example.jp
  ```
- `example.com` と書けば `www.example.com` や `cdn.example.com` など**サブドメイン全部**が対象
- 正確な一致ではなく「そのドメインとその下位ドメイン全部」なので、広告CDNなどを丸ごと黙らせるのに使えます

## 表示の読み方

- **アイコンのバッジ数字**: 今のタブで検出中のアイテム数。消したいときはポップアップの「クリア」
- **ステータス行**（ポップアップ上部）: 直近の操作結果が1行で出る。「保存しました: ファイル名」「失敗: 理由」「CDNが…再取得しています」など
- **各アイテムの右側ボタン**: 「保存」（通常時）→ 処理中は「キュー追加 / 取得中 / 〇% / 保存中 / 再試行中 / 録画中・停止」→ 完了で「保存」に戻る

## 検出されない・保存できないケース

| ケース | 理由と対処 |
|---|---|
| ページを開いただけで一覧が空 | 仕様です。再生を始めると出てきます |
| 「再スキャン」を押しても出ない | そのページがまだメディアを読み込んでいない可能性。動画を一度再生してみる |
| Netflix等の有料ストリーミング | DRM保護されているため**原理的に不可能**です。対応予定もありません |
| blob:だけでm3u8が見えないサイト（MSE方式） | 検出が部分的になります。DevToolsのNetworkタブで m3u8/mpd のリクエストが見えるなら Media Sniper も拾えます |
| 保存したmp4が再生できない/真っ黒 | DRMやMSE由来の断片の可能性。そのサイトでは非対応と考えてください |
| 拡張を更新した直後に動かない | 拡張機能ページで↻再読み込み、または一度削除して読み込み直し |
| 長い動画で止まったように見える | 大きいHLSは変換に時間がかかります。ボタンが%表示の間は正常に進行中です |

## 他の拡張機能との併用

ファイル名の指定方法に工夫をしてあり、Video DownloadHelper等の他のダウンロード系拡張と**干渉しません**。逆に他の拡張が原因で保存に失敗した場合も、その旨がステータス行に表示されます。

過去に「あるダウンロード拡張が他の拡張の保存を壊す」という事故がChromium系でありましたが、Media Sniperはその引き金となるAPIを意図的に使っていないため、併用環境でも安全に動作します。

## データの保管と消え方

| データ | どこにある | いつ消える |
|---|---|---|
| 検出アイテムの一覧 | ブラウザのセッション領域 | **ブラウザを閉じたら消える** |
| 設定（フォルダ名・閾値・除外ドメイン） | ブラウザのローカル領域 | 拡張を削除するまで残る |
| 保存したファイル | `~/Downloads` | 自分で消すまで残る |

外部サーバーへの送信は一切ありません。拡張が通信するのは、あなたが保存しようとしたメディアの配信サーバー（CDN）に対してのみで、それは通常のブラウジングで発生する通信と同一のものです。

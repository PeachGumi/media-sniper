# Third-Party Notices

Media Sniper includes third-party software. This document records the exact
source/build provenance used for release artifacts and the corresponding-source
path supplied to recipients.

## libav.js / FFmpeg WebAssembly

Release runtime files:

- `src/libav/libav-6.10.9.0-media-sniper.wasm.mjs`
- `src/libav/libav-6.10.9.0-media-sniper.wasm.wasm`
- `src/libav/PROVENANCE.json`

The historical path
`src/libav/libav-6.5.7.1-h264-aac-mp3.wasm.mjs` is now only a small Media
Sniper compatibility shim that delegates to the reproducible runtime above.
The old `v6.5.7.1-61-g823eb97` WASM binary is not included in the distribution.

### Exact build provenance

The bundled runtime is generated by `.github/workflows/rebuild-libav.yml` from:

- upstream repository: `Yahweasel/libav.js`
- upstream tag: `v6.10.9.0`
- upstream commit: `c80e885c3461f7bb7ea565c9631b34243ae0dbf1`
- libav.js version: `6.10.9.0`
- FFmpeg version: `9.0`
- Emscripten version: `6.0.5`
- Media Sniper variant: `media-sniper`

The exact fragment list is version-controlled in `tools/libav/config.json` and
repeated in `src/libav/PROVENANCE.json`. The variant is intentionally designed
for demuxing, HLS/crypto protocol handling and stream-copy remux/mux. Media
Sniper does not request H.264/AAC encoder or decoder fragments for this runtime.

Current artifact SHA-256 values are recorded in `src/libav/PROVENANCE.json`.
CI recomputes the hashes and fails if a generated runtime differs from the
recorded provenance.

### Corresponding source and rebuild recipe

The complete rebuild recipe is documented in `tools/libav/README.md`. The build
workflow checks out the pinned upstream tag, generates the exact custom variant
with upstream `configs/mkconfig.js`, extracts the dependency sources, builds the
WebAssembly ES-module target and records the resulting hashes.

For every approved `v*` GitHub Release, release CI also creates and attaches:

- `media-sniper-libav-corresponding-source.tar.gz`
- `media-sniper-libav-corresponding-source.tar.gz.sha256`

That source bundle contains the pinned libav.js source checkout, generated
Media Sniper variant configuration, extracted dependency source trees/archives,
`tools/libav/config.json`, the rebuild documentation and the shipped
`PROVENANCE.json`. The release process verifies the checked-out upstream commit
before creating the bundle.

This source bundle is attached alongside the extension ZIP so recipients do not
need to infer which generic upstream checkout corresponds to the binary they
received.

### Historical artifact note

Older Media Sniper revisions shipped a `v6.5.7.1-61-g823eb97` libav.js artifact
whose exact corresponding source/build recipe could not be reconstructed from
repository history and whose generated JavaScript had a recorded downstream
stdin patch. That artifact is deliberately not used or packaged by the new
release path. It remains visible only in repository history for auditability.
